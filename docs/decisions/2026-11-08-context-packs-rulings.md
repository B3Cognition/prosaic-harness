# Context-pack implementation rulings

This is the exhaustive chronological register from native implementation and the
independent review. Later entries may refine earlier ones. The public context-pack
guide describes the resulting contract. Each entry preserves the decision and its
reason; explicit cost notes clarify consequences where the original ledger used
operational wording. No minor review findings were deferred.

1. Setup: Ruling: Relocate native worktrees under the corresponding writable project roots — app-created paths were outside the sandbox and prevented edits — app attachments may retain stale paths; git branches and originals remain intact. Cost if wrong: App attachments may need to be reopened at the relocated paths.

2. Task 1: Ruling: Use closed locator objects {kind: whole|utf8Range|jsonPointer|record} with start/end, pointer or id fields — design names semantics but leaves their JSON shapes open — later public consumers must use these shapes consistently. Cost if wrong: Changing these public locator shapes later would require consumer migration.

3. Task 1: Ruling: Enforce task slot shape in pure spec admission; enforce nonempty selected value in composition and input-only source binding in workflow admission — spec cannot infer a future host source binding — those later checks must remain mandatory. Cost if wrong: A later admission layer accidentally removed could admit an invalid mandatory task.

4. Task 0: Ruling: Store baseline metadata under existing ignored .tools (Runtime) and plan workspace (Harness), rather than add tracked ignore changes for output/context-packs — these directories already have the required private scratch lifetime — links to scratch evidence are local only; immutable release provenance remains committed. Cost if wrong: Scratch logs are machine-local; they do not replace durable release provenance.

5. Task 5: Ruling: An omitted input_profile on the explicitly new prepare_turn_variants API uses context-input-variants-v1 — the API itself opts into v3 and must preserve legacy prepare_turn defaults — consumers wanting a domain-specific schema must pass their explicit profile. Cost if wrong: A caller omitting a domain profile receives only the generic variant schema.

6. Task 5: Ruling: Fund optional trial bytes using the exact JSON-encoded current-user-string delta from the verified base, then compare it with the constructed native size before counting — source history, instructions, tools and output framing stay fixed, and no extra full candidate can be encoded outside the budget — a future encoder that changes this invariant fails bindingMismatch rather than dispatching. Cost if wrong: A changed encoder invariant refuses the invocation instead of dispatching.

7. Task 6: Ruling: Required node pins require the pinned agent node to exist; a missing node is not an unused default — otherwise a proposed graph could silently evade a host's specific node requirement — hosts sharing pins across unrelated graphs must provide graph-specific node pin maps. Cost if wrong: Host pin maps reused across unrelated graphs can refuse otherwise valid graphs.

8. Task 6: Ruling: Trusted agentContextPacks keys must name an agent used by that workflow; host-wide agent_defaults may contain unused catalogue entries — reject authoring typos while allowing reusable host bindings — hosts intending unused YAML defaults must move them to host bindings. Cost if wrong: Unused YAML defaults must move to reusable host bindings.

9. Task 7: Ruling: project_step requires an explicit controller_validation_context CheckContext and accepts explicit required_dependencies — original per-step arguments cannot reconstruct the wider controller's all-artifact view or distinguish optional dependencies — callers must supply the real state-derived context; omission fails rather than silently narrowing validation. Cost if wrong: Integrators must supply the actual full controller context; omission refuses projection.

10. Task 7: Ruling: Model headers automatically include authenticated human choice metadata, while free-form human response bodies remain private unless supplied as declared evidence — arbitrary response bodies are business context and would bypass declared-only projection — consumers needing those bodies must deliberately capture them into a permitted pack source rather than relying on implicit old-payload copying. Cost if wrong: An agent cannot see a human response body until the host explicitly declares it as evidence.

11. Task 9: Ruling: Pack-enabled nodes require finite host invocation caps, including unguarded nodes — Runtime profiled turns and worst-case pre-effect reservations cannot execute under the legacy None allowances — hosts must provide the existing provider/tool cap fields; native factory copies seal those host caps and YAML declares them explicitly. Pack-free defaults remain untouched. Cost if wrong: Pack-enabled hosts lacking finite invocation caps cannot execute.

12. Task 9: Ruling: The source registry admits up to 256 inert aliases while per-invocation snapshots retain the 16-source default — applying a snapshot limit to the whole workflow registry prevented independent nodes from using different small packs — the static descriptor can be larger, and its actual bytes/nodes remain subject to existing registration/storage caps. Observed RED with a 25-alias registry; capture still selects only the one declared task source. Cost if wrong: A large registry can still hit registration or storage descriptor bounds.

13. Task 9: Ruling: Packed workflow records reserve a combined 64KiB output ceiling, further bounded by host max_output_bytes — reserving the legacy 100KiB independently for stdout and stderr cannot fit the unchanged 1MiB receipt even for a tiny pack — Task 13 must enforce this effective limit on Runtime admission and materialized results; pack-free legacy limits remain unchanged. A host requiring larger packed output needs a separately admitted capacity profile, not a silent cap increase. Cost if wrong: Packed output larger than the effective 64 KiB allowance needs a separately admitted capacity profile.

14. Task 10: Ruling: Released FileRunStore has no marker reader, so a marker added inside its directory cannot exclude old binaries — explicit workflow migration moves the existing owned directory intact to a deterministic versioned sibling and puts a regular contract-2 marker file at its old directory address; old code fails on its first lease/read/write because that path is no longer a directory — old FileRunStore.check_ready itself performs no I/O and cannot be retroactively made to reject. Hosts must drain all writers before migration, as required for other backends. Existing checkpoint/receipt bytes stay unchanged; no body/blob protocol is introduced. New packed workflow documents use the exact canonical UTF-8 writer reserved by capacity.py; legacy documents retain their original writer. Cost if wrong: An old readiness probe can report success even though the first real I/O refuses the migrated namespace.

15. Task 13: Ruling: Workflow context policy/counter registry are host-only Harness constructor options, with sealed assembly descriptor material in the opted-in run — Runtime already owns the token fitting API and workflows had no prior token-policy surface; avoid model-authored counters or YAML executable registration — consumers must provide the same admitted descriptor when executing a new/recovered counted invocation. Saved receipt adoption must remain possible without executing counters; missing registration may block a subsequent invocation, not settlement. Cost if wrong: Missing or changed counter registration can block a subsequent invocation after settlement.

16. Task 13: Ruling: Private use authorization has an explicit ContextUse v2 profile/digest and all declared present origins from the full frozen controller view — selected model snapshot references alone underdescribed existing private guard/controller facts — ContextUse v1 bytes remain exact when no private binding is supplied, and host callbacks must understand the new private profile when applying source-specific validation/read policy. Full private facts are retained; model evidence remains declared-only. This adds metadata/validation cost bounded by existing private record caps rather than silently shrinking validation input.

17. Task 13: Ruling: Authorize the richest monotone exposure union once before fitting, then recheck selected use at the durable dispatch boundary — authorizing each candidate repeated equivalent host work and could exhaust host callback budgets — a host sees two meaningful logical boundaries, and must use cancellation for revocation during an already admitted effect. Restored attempts recheck current use before dispatch. Cost if wrong: In-flight revocation needs cancellation; already disclosed bytes cannot be retracted.

18. Task 13: Ruling: Public workflow run/resume/status results require retainedRead independently of inference/validation; authorization runs after internal settlement — denied views must not strand completed effects — callers may receive a closed denial after their authorized operation completed and must reconcile status under a permitted view. Private/model retained views have separate authorization uses; private view includes a digest of the entire returned checkpoint. Cost if wrong: An authorized effect may complete while its returned view is denied; callers must reconcile instead of blindly retrying.

19. Task 13: Ruling: Invalid human actions retain existing zero-write behavior and safe structural error codes, adding safe-feedback-v1 only to opted-in exception dictionaries — persisting feedback for an invalid action would change CAS semantics — opted-in callers should consume the additive feedback field, while legacy dictionaries remain exact. Missing gate fields set gateInputInvalid on the blocked checkpoint. Cost if wrong: Opted-in clients must read the additive safe-feedback field; invalid actions still do not advance CAS state.

20. Task 13: Ruling: Native pack nodes use no Runtime filesystem workspace — factory nodes already prohibit acquisition/read roots and rely on declared captured facts or custom tools, while the old execution directory is temporary — native builtin tools requiring a workspace fail admission; static Markdown workflows keep their stable directory binding. This preserves exact workspace identity on restart without weakening Runtime restoration. Cost if wrong: Native filesystem tools needing a workspace refuse admission.

21. Task 13: Ruling: Abandoning a prepared-but-never-dispatched frame records zero provider tokens, preserving its unknown counter reservation in the old frame — the durable dispatch marker precedes every provider effect — this relies on Runtime's on_admitted ordering; dispatched unknown provider attempts retain token_usage=None and the existing usage_unknown block. Cost if wrong: If the dispatch-marker ordering regresses, the zero-provider-charge inference could become unsound.

Global quotas remain unchanged. Cost if wrong: Incorrect overlap accounting could under-reserve a completed record; materialized bounds and installed witnesses gate it.
